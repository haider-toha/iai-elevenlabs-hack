# 02 — Removal Surface Area (research)

**Topic:** Everything safe to delete to reach a backend-less, single-package Next.js
cold deploy of Marginalia — each item with evidence, plus a separate "do NOT delete /
must relocate" list and a flagged set of sequencing risks.

Repo root: `/Users/haidertoha/Code/i.ai_hackathon`. All paths absolute. Evidence is
either a grep with zero source hits (`app/ components/ lib/ scripts/`, excluding
`.next/` and `node_modules/`) or a direct file read on 2026-06-26. Builds on Phase 1
(`plan/simplification/01-exploration/*`) — those facts are not re-derived here.

---

## TL;DR — the single authoritative verdict

- **Two whole top-level trees go: `backend/` and `supabase/`.** Nothing in either is
  on the demo runtime path once the two letters are inlined and the QR + prompt are
  relocated. Combined that removes FastAPI, Poetry/Python, asyncpg, Postgres,
  Supabase CLI, Docker, all migrations/seeds, both ops scripts, and the GOV.UK corpus.
- **Three frontend files are deletable outright** (`scripts/export-letter.ts`,
  `scripts/copy-govuk-assets.ts` — *conditionally*, and the `out/` artifacts), plus
  three dead public images and one block of dead code (`getHealth`/`Health`).
- **Removal is partly *sequenced*, not free-standing.** `supabase/` is the verbatim
  source of the two letters; `backend/prompts/letter_explainer.txt` and the QR are
  live couplings. Delete those producers only *after* the inline replacements land
  (the inlining is a different work item — this report only enumerates the surface).
- **Two npm deps fall only after their script does** (`govuk-frontend` after the copy
  script; `@playwright/test`+`playwright`+`tsx` after the two scripts). Do not strip
  them first.
- **The cold-deploy landmine is unchanged and must be fixed in the same pass:**
  `frontend/public/vendor/govuk-frontend.scoped.css` and `govuk-logotype.svg` are
  git-ignored, untracked, and regenerated by **no** script. Removing `copy-govuk-assets.ts`
  is only safe *after* these two files are un-ignored and committed.

**Removing `getLetter`/Supabase drops nothing from deps by itself** — `getLetter` uses
only `fetch` + `zod`; there is no `@supabase/*` dependency installed to remove (it was
never added). The only dep deletions are the three conditional ones above.

> **QR replacement may ADD a dep — decide before building.** The backend QR uses
> Python `qrcode`; the frontend has **no** JS QR library today. Replacing it three ways:
> (a) pre-render two static PNGs into `public/` — **adds no dep** (recommended; only
> `maria-p2`/`maria-p800` exist), but bakes a fixed deploy host into the encoded URL;
> (b) a Next route handler — **adds `qrcode`**; (c) client-side encode — **adds a dep**.
> Net: removing the backend does not force a new dep, but the dynamic-host QR option
> would. The preview already has a working `<a href="/l/{id}">`, so the scannable image
> is the only thing at stake.

## C. The cold-deploy landmine (must fix in the same pass — flagged, not a delete)

`frontend/public/vendor/` is entirely git-ignored (`.gitignore:10`) and **none** of its
files are tracked (`git ls-files frontend/public/vendor/` → empty; `git check-ignore -v`
confirms `scoped.css`, `logotype.svg`, and `min.css` all ignored). The only producer,
`copy-govuk-assets.ts`, emits **only** `min.css` (which is unused at runtime). So on a
fresh clone + `pnpm install` + build, the two runtime-critical files (`scoped.css`,
`logotype.svg`) are **missing** → the `/actions/*` pages and the in-chat GOV.UK overlay
render unstyled and the crown 404s.

**Ordering constraint:** commit `scoped.css` + `logotype.svg` (un-ignore the path or
add explicit `!` exceptions) **before** deleting `copy-govuk-assets.ts` and the
`govuk-frontend` dep. Otherwise you remove the only mechanism touching `public/vendor/`
while the live files remain untracked.

## D. Flagged ambiguities (do NOT greenlight blindly)

1. **`backend/scripts/setup_eleven_agent.py` + `backend/data/govuk/*.md`** — setup-time,
   not runtime. The provisioned agent (`NEXT_PUBLIC_AGENT_ID`) is a runtime *prerequisite*
   with `conversation_config_override` + `auth` enabled. Deleting `backend/` deletes the
   only way to re-provision a *fresh* ElevenLabs workspace. **Decision needed:** if the
   deploy points at the already-provisioned agent, delete freely; if a clean workspace
   must be reproducible, relocate the script + the six KB markdown files + its
   `XI_API_KEY`/`XI_VOICE_ID_*` somewhere outside `backend/` first. Not a runtime blocker
   either way.
2. **`supabase/` deletion is sequenced after letter inlining.** It is the verbatim
   source of the two letters. Safe to delete only once the inline map exists and is
   verified (or accept the verbatim capture in 03-data.md as the record). Same for
   `NEXT_PUBLIC_API_URL` and the QR.
3. **Secret hygiene.** `frontend/.env` holds a live `XI_API_KEY`; `backend/.env` holds
   that plus a Supabase **secret** key. The Supabase secret dies with `backend/`; the
   `XI_API_KEY` must become a platform secret on the SSR host and be **rotated** before
   any public deploy (it has been printed in the Phase-1 docs).
4. **`README.md` (root, 1.6 KB)** references the old `make`/dev workflow; not a runtime
   asset, but update it when the Makefile targets change (out of scope for delete).
5. **Minor doc drift (not load-bearing):** 01-frontend.md attributes the `public/vendor/`
   ignore to `frontend/.gitignore`; that file does **not** exist — the rule lives in the
   **root** `.gitignore:10`. Same outcome, corrected for accuracy.
